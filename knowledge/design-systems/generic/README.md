# generic — بدون design system

> updated: 2026-08-12

این پوشه یک DS واقعی نیست — یک **placeholder صریح** برای پروژه‌هایی که
هیچ کتابخانه‌ی کامپوننتی ندارن (نه Chakra، نه Bootstrap، نه MUI، هیچی).

## کِی استفاده کنیم

- `.dev-engine.json` پروژه: `"ds": "generic"`
- پروژه فقط HTML/CSS خام یا utility-only (مثلاً Tailwind بدون component library) می‌نویسه
- پروژه هنوز تصمیم نگرفته چه DS ای استفاده کنه (early scaffold)

## چرا حذفش نکردیم، یه فایل جدا ساختیم

اگه پروژه‌ای `ds` رو خالی می‌ذاشت یا نامعتبر می‌ذاشت، `dev-engine doctor` سکوت می‌کرد
یا خطای گنگ می‌داد. با `ds: "generic"` انتخاب **آگاهانه** و **صریح**‌ـه —
doctor می‌فهمه «DS نداره، نه اینکه config خرابه» و طبق همین گزارش می‌ده،
نه silently pass.

## ⚠️ مهم — این یعنی «نداشتن DS»، نه «هر DS ناشناخته»

اگه پروژه واقعاً از یک کتابخانه استفاده می‌کنه (حتی اگه اینجا seed نشده)،
**نباید** از `generic` استفاده کنی. باید یک پوشه‌ی DS واقعی بسازی:
کپی از `../_TEMPLATE/`، پر کردن `ds.json` و بقیه‌ی فایل‌ها. `generic`
فقط برای نبودِ واقعیِ لایه‌ی DS ـه، نه میان‌بر برای DS مستندنشده.
